Comment lire les diapos Chaque diapo suit le même schéma : un titre (l'idée), une définition en une ligne, 3 ou 4 puces d'explication qui apparaissent une par une, et un encadré 💡 À retenir. Pour présenter : lire le titre, expliquer chaque puce avec vos mots au moment où elle apparaît, finir par la phrase 💡. Le texte est là pour vous guider et pour le professeur ; ne le lisez pas mot à mot.

2Le prétraitement : texte → tokensDiapo 7 · A
💡 On ne garde que les mots porteurs de sens : les mots vides sont partout et ne distinguent aucun post.
Comment le présenter (4 puces)
  1. Minuscules : Derby = derby.
  2. Découpage par regex ; #football → football.
  3. Mots vides retirés (le, de, au…).
  4. Pas de lemmatisation : joueur ≠ joueurs (limite assumée).

Chiffre : p01 → 50 tokens bruts → 29 conservés.

3TF-IDF : tokens → vecteurDiapo 8 · A
💡 Un mot pèse lourd s'il est fréquent dans le post (tf) et rare dans le corpus (idf). Chaque post devient un vecteur de longueur 1.
Comment le présenter
  1. Formule : poids = tf × idf, idf(t) = ln((1+n)/(1+df(t))) + 1.
  2. tf = « compte ici » ; idf = « rare ailleurs » : football 2,41 vs derby 4,02.
  3. Normalisation L2 : longueur 1, court ou long.
  4. Résultat : 564 nombres par post, 3,3 % non nuls.
Montrer

Diapo : les barres derby 0,362 · victoire 0,362 · match 0,263 · football 0,109.
App : onglet 🔬, bloc ③ Poids TF-IDF.
Code : recommender/model.py:19 make_vectorizer (analyzer=preprocess, ligne 22) · model.py:36 __post_init__ (fit_transform)

Question piège : « Pourquoi ce +1 dans l'idf ? » → C'est le lissage de scikit-learn (smooth_idf=True) : pas de division par zéro, et un mot présent partout garde un poids non nul.

4La similarité cosinusDiapo 9 · A
💡 Deux textes qui partagent des mots importants pointent dans la même direction. Vecteurs de longueur 1 ⇒ cosinus = somme des produits des mots communs.
Comment le présenter
  1. Chaque texte = une flèche ; cosinus = angle.
  2. cos = 1 : mêmes mots ; cos = 0 : aucun mot commun.
  3. Seuls les mots communs comptent → explicable.
  4. Indépendant de la longueur (≠ distance euclidienne).
Montrer

Diapo : T1/T2 → stade 0,474 × 0,474 = 0,224 ; T3 → 0.
App : onglet 🧪 → B (paires de posts).
Code : model.py:85 cosine_between · model.py:81 similarity_scores

Question piège : « Pourquoi pas la distance euclidienne ? » → Elle dépend de la longueur des textes ; le cosinus compare seulement des directions.

7Le score et son explicationDiapos 12–13 · M
💡 Score = cosinus profil ↔ post. Chaque mot commun apporte poids profil × poids post ; la somme est exactement le score.
Comment le présenter

  2. p04 = supporters 0,059 + match 0,029 + stade 0,022 + football 0,020 + équipe 0,019 = 0,148.
  3. Ex. : supporters = 0,217 × 0,271 = 0,059.
  4. Diapo 13 : p18 (pâtes) n'a qu'un mot commun, rapide (0,029) → polysémie.

7 · Questions probables du professeur

QuestionQuiRéponse courte
Pourquoi TF-IDF et pas des embeddings ?AObjectif pédagogique : TF-IDF est entièrement explicable. Les embeddings géreraient foot/football, mais sont une boîte noire et demandent un modèle téléchargé.
Pourquoi le cosinus ?AIl compare des directions, pas des longueurs ; avec des vecteurs normalisés, c'est un produit scalaire décomposable par mot.
Comment calculez-vous l'idf ?Aln((1 + n)/(1 + df)) + 1 (smooth_idf=True), écrit explicitement dans make_vectorizer(), vérifié par un test.
Pourquoi une moyenne pour le profil ?MLe plus simple : le centre des goûts. Limite : tous les likes pèsent pareil (désert en tête après p10).
Les scores sont faibles (0,15) ?MTextes courts, peu de mots communs. Seul l'ordre compte. Ce n'est pas une probabilité.
Pourquoi des pâtes dans un feed football ?MLe seul mot rapide : polysémie. Montré volontairement (onglet 🔬, p18).
La catégorie est-elle utilisée ?MNon : seulement titre, description, hashtags (preprocessing.py:40).
L'exploration est-elle aléatoire ?MNon, déterministe ; elle ne modifie aucun score.
Différence avec le collaboratif ?AIl utilise les autres utilisateurs et ignore le texte ; il faut beaucoup d'utilisateurs. Les vrais systèmes sont hybrides.
C'est comme TikTok ?ANon. Les plateformes apprennent sur des milliards d'interactions (temps de visionnage, partages). Nous illustrons une brique de base.
La démo prouve-t-elle les bulles de filtre ?ANon : 1 utilisateur fictif, 40 posts. Il faudrait de vrais utilisateurs, une durée, une mesure de diversité, un groupe témoin.
Comment améliorer le modèle ?ALemmatisation, synonymes, n-grammes, embeddings, pondération temporelle, signaux négatifs, hybride.
Comment savez-vous que c'est juste ?M44 tests : normes, idf, cosinus = produit scalaire, Σ contributions = score, chaque effet de la démo (python -m pytest -q).
Et avec un million de posts ?MMatrice creuse, produit rapide ; en production : recherche approximative de voisins et pré-sélection de candidats.
